## 1. Introduction
A browser test is more useful when it leaves a clear record of what was checked and what happened. For this assignment, I prepared a Selenium test plan and Python logging script for my published portfolio. The aim is to make each run easier to review, troubleshoot, and compare with later runs.

The script records the run date and time, website URL, browser and version, operating system, each test ID, expected and actual results, PASS/FAIL status, duration, and supporting failure details. Each run gets a unique timestamped log filename so earlier records are not overwritten.

## 2. Test plan
The positive checks cover the homepage and the main About, Expertise, Portfolio, Skills, and Contact sections. A seventh negative check deliberately looks for a section named `missing-section`, which should not exist. This check demonstrates how an unsuccessful test is recorded.

See [TEST_PLAN.md](TEST_PLAN.md) for the complete test plan table.

## 3. Logging design
The script uses Python's logging library rather than relying on print statements as test evidence. INFO entries record normal progress and passing checks. ERROR entries record failures. Every test record includes its ID, description, expected outcome, actual outcome, status, duration, and current page URL.

When a test fails and the browser remains available, the script attempts to save a screenshot under `logs/screenshots/`. The script continues to later tests instead of stopping at the first failed assertion. At the end, it writes a summary of total, passed, failed, and elapsed time.

## 4. How to run
1. Install Python 3.10 or later and Google Chrome.
2. Install the dependency: `python -m pip install -r requirements.txt`.
3. Run: `python test_portfolio.py`.
4. Review the timestamped log in `logs/` and any failure screenshots.
5. Run the script at least three times and commit the generated log files as evidence.
